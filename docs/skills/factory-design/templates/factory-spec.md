### Mission

Describe the production-line objective in one paragraph:
- what backlog inputs enter this factory,
- what shipped outcomes it must produce,
- what "done" means in measurable terms.

### Scope boundaries

- **Factory** = end-to-end autonomous system (outer loop + production lines + recovery + telemetry).
- **Role** = contract for one job in that system (Supervisor, Coder, Reviewer, etc.).
- **Skill** = optional reusable guidance a role may invoke.

Role and skill are distinct contracts. Roles may load skills, but role IO/retry/success criteria remain authoritative.

### Mental models preserved by this spec

Confirm this spec preserves the Factory Design skill mental model:
- deterministic control flow,
- durable state in external systems,
- explicit ownership for every transition,
- measurable outcomes (not stage churn),
- infra/work repo separation.

## 4) Role matrix (contracts are mandatory)

Each role contract must include: responsibility, input contract, output contract, retry/review behavior, success criteria, and node-level model guidance.

### Contract matrix

| Role | Responsibility | Input contract (required keys) | Output contract (required keys) | Retry/review behavior | Measurable success criteria | Model-selection guidance |
|---|---|---|---|---|---|---|
| Supervisor | Own outer loop health/routing/recovery/dispatch. | `state_snapshot`, `active_runs`, `capacity_limits`, `action_items` | `dispatch_decision`, `recovery_actions`, `status_artifact` | Bounded retries on transient infra; deterministic escalation path. | Tick completes; no unowned stuck state; incidents routed. | Use reasoning-focused model for gate/routing decisions. |
| Issue/Triage Writer | Convert goals into executable issues with dependencies. | `goal_spec`, `constraints`, `milestone_context` | `issue_batch`, `acceptance_criteria`, `dependency_map` | Revise when ambiguity detected; block duplicate issue emission. | Downstream coder/reviewer execute with no clarifying questions. | Prefer strong structuring model; enforce schema in output. |
| Coder | Implement scoped issue work. | `issue_spec`, `repo_context`, `test_contract` | `commit_set`, `change_summary`, `verification_evidence` | Bounded revision loop from reviewer/judge feedback. | Acceptance criteria met with passing deterministic checks. | Primary implementation model; per-node override allowed. |
| Reviewer | Validate correctness and scope conformance. | `issue_spec`, `diff_scope`, `evidence_payload` | `review_verdict`, `reason_codes`, `revision_notes` | Must return actionable corrections on rejection. | High defect precision + low false reject rate. | Higher-reasoning model with strict contract checks. |
| Merger | Integrate approved work and close state transitions. | `approved_branch`, `merge_policy`, `closure_requirements` | `merge_result`, `closure_comment`, `state_updates` | Deterministic conflict path; escalate policy blocks. | Merge completes; no orphan marker/issues. | Deterministic tooling first; minimal LLM path. |
| Judge | Independent scenario-based quality gate. | `judge_context_identity`, `scenario_set`, `acceptance_criteria`, `evidence_payload` | `judge_result`, `judge_notes`, `failure_category`, `judge_context_identity` | Bounded retries by failure category; route deterministically on exhaustion. | Pass/fail signal correlates with production outcomes. | Use stable evaluation model with explicit scenario contract. |

## 6) Topology guidance (choose one explicitly)

### Option 1: Co-located factory + product work

- `factory_repo == target_repo`
- Infra bugs may still route to a dedicated tracking space, but must be explicit.
- Ownership is simpler; enforce role boundaries via contracts, not repo separation assumptions.

### Option 2: Split infra + target repo

- `factory_repo != target_repo`
- `infra_issue_repo` is explicit and may differ from both.
- Factory code/issues stay in infra repo; shipped product work lands in target repo.
- Never conflate infra failure remediation with product issue execution.

Record chosen option: `{{topology_option}}` and explain why.
