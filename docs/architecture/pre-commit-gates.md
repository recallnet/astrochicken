## Pre-Commit Gate Contract (Operator + Contributor Reference)

This section is the canonical operator-facing contract for `.githooks/pre-commit`.
When hook behavior changes, update this document **in the same change** as `.githooks/pre-commit`, `scripts/pre-commit-staged-file-classifier.mjs`, and/or `scripts/run-platform-invariant-gates.mjs`.

`pnpm test` is the fast local verification path. It runs only the cached package tests and repo-contract suites that match the current change path; when no path filter can safely narrow scope, it runs both. `pnpm test:strict` runs the exact strict gate proof outside the hook. `git commit` remains the strongest local checkpoint. `.githooks/pre-commit` runs `node scripts/run-gates.mjs --profile strict --staged-file-list <filelist>` and must fail closed on any strict-profile regression. The `strict` profile is the local superset of `fast`: it preserves deterministic staged routing, includes every fast-profile gate, and layers in the strict-only local checks. That strict-only set now includes global docs freshness review pressure through `docs_freshness`: active governed docs are expected to stay current, and stale docs must be updated, re-reviewed, reclassified, or deleted before commit. The docs contract path also includes `docs:postgres-canonical-truth:check`, which validates the checked-in Postgres migration ledger shape, commit-type sequencing, adjacent `cutover+grace-delete`/`delete` pairing, and required review header fields so migration review discipline is enforced by repo checks instead of reviewer memory. Fast/strict/full now also share the repo-wide `phase1_gate_readiness` audit, which proves the future Phase 1 graph transport, runtime internal-CLI, and command-thinness flips all point at the same canonical active surface and checked-in violation inventory, the repo-wide `phase1_ownership_mapping` audit, which proves every remaining Phase 1 active-surface violation and every relevant legacy blast-radius surface has one explicit checked-in owner, the repo-wide `phase1_burndown_finalization` audit, which freezes the exact Phase 1 elimination set and wrapper-role classification that the migration must burn down, the staged `workflow_instrumentation_helper_contract` audit, which blocks newly changed Hatch workflow/action lifecycle telemetry wiring outside the standard helper surface, the repo-wide `canonical_event_emitter_ownership` audit, which blocks canonical factory-domain event emission from Hatch prompt/manager surfaces and other forbidden LLM-owned paths, the staged factory-domain `github_adapter_boundary` audit, which blocks newly changed `packages/factory-ops` surfaces from importing direct `gh` transport helpers or spawning GitHub CLI transport outside `@hatch/github-adapter`, the repo-wide `github_truth_read_boundary` audit, which inventories execution-critical `gh issue view`, `gh api`, and GraphQL reads outside `@hatch/github-adapter`, fails closed on new offenders, and keeps the checked-in allowlist and inventory in sync with the remaining migration debt, the staged `reactor_collector_contract` audit, which blocks newly changed active Hatch control-plane runtime entrypoints from booting bespoke Redis/Langfuse telemetry paths or hand-rolled OTLP transport outside the collector-backed OTel helper path, the repo-wide `boundary_schema_contract` audit, which blocks governed boundary JSON Schema drift and rejects unregistered boundary authoring modules outside the shared Zod export path, the repo-wide `sync_openapi_contract` audit, which blocks drifted synchronous HTTP OpenAPI outputs and rejects unregistered sync contract authoring modules or consumers that bypass the canonical sync contract source, the repo-wide `asyncapi_contract` audit, which blocks drifted asynchronous contract outputs and rejects unregistered async contract authoring modules or producers/consumers that bypass the canonical async contract source, the repo-wide `capability_contract` audit, which blocks capability packages that do not expose versioned standard contract outputs, rejects legacy `capability.json` exports or files, rejects undeclared governed graph/skill entrypoints, and rejects newly discovered governed capability packages without a canonical contract source, the repo-wide `cloudevents_contract` audit, which blocks legacy semantic event envelopes on governed event paths, rejects unregistered CloudEvents authoring modules, and rejects producers or consumers that stop importing the canonical CloudEvents contract source, the repo-wide `oci_artifact_contract` audit, which blocks drifted OCI taxonomy outputs, rejects unregistered governed artifact classes, rejects unregistered governed publisher callsites, rejects missing lifecycle policy on governed durable artifact classes, rejects bespoke lifecycle fields on governed publisher paths unless they come from the shared lifecycle helper, rejects direct ORAS usage on governed publication paths, rejects legacy private attachment identifiers or raw subject wiring, and rejects durable artifact publication that bypasses the canonical OCI helper surface, the repo-wide `artifact_trust_contract` audit, which blocks required governed artifact classes without the canonical signing/attestation/provenance policy, blocks governed publisher paths that bypass the shared trust helper, and blocks host-runtime release trust flows that drift away from the standard trust bundle surface, the repo-wide `dispatch_latency_slo_contract` audit, which blocks missing or oversized dispatch latency budgets, blocks missing or non-demoted maintenance cadence, and blocks daemon runtime paths that stop routing SLO/cadence enforcement through the shared dispatch policy owner, the repo-wide `reactor_dispatch_contract` audit, which blocks mothership hot-path dispatch logic from remaining in the maintenance supervisor graph and blocks the governed dispatch reactor from drifting away from the canonical executable-goal selection and detached goal-spawn surface, and the repo-wide `lineage_governance_contract` audit, which blocks missing governed OpenLineage-compatible registry outputs, blocks duplicate lineage-normalization helpers outside the shared lineage owner, and blocks Marquez/Atlas-style governance dependencies from entering the execution hot path. The whole-repo workflow/runtime parity audits (`workflow_ir_runtime_parity_e2e` and `runtime_conformance_matrix`) stay enforced in the `full` profile for pre-merge proof instead of blocking every fast/strict local commit. `run-platform-invariant-gates.mjs` is the bounded fan-out owner for `platform_invariants`; it emits `gate_plan` telemetry with `max_parallel_entries=<n>` and defaults to a laptop-safe concurrency of `2` unless `HATCH_PLATFORM_GATE_MAX_CONCURRENCY` explicitly overrides it. `git push` is a lighter transport-time checkpoint and currently runs `node scripts/run-gates.mjs --profile fast --staged-file-list <filelist>` for pushes to `main`. `git merge`/PR CI remains the strongest whole-repo checkpoint via `pnpm --silent qa:pre-merge` (`run-gates --profile full`).

### Canonical gate order (deterministic)

For any staged commit, the hook runs in this fixed order:

1. **DOT/state preflight checks**
   - DOT validation **and `scripts/lint-dot.mjs`** (wrapper over dot-lint) for every staged `.dot` file (`phase=dot_validate`)
   - context propagation contract enforcement (`phase=context_propagation_contract`, runs `node scripts/check-context-propagation-contract.ts`); triggers when staged paths include any `.dot` file or context-contract implementation surfaces (`apps/hatch/src/pipeline/handler/**`, `apps/hatch/src/pipeline/handler/register.ts`, `scripts/check-context-propagation-contract.ts`, `scripts/handler-context-contract.json`); gate runtime passes staged scope via `--staged-file-list <filelist>` in fast/strict and `--all-tracked` in full profile
   - pipeline segment coverage enforcement (`phase=pipeline_segment_coverage`, runs `node scripts/check-pipeline-segment-coverage.ts`); current contract-first stub triggers when staged paths include any `.dot` file or any `packages/**` path (`hasDotFiles || hasPackagesPaths`), receives staged scope via `--staged-file-list <filelist>` (or `--all-tracked` in full profile), and emits deterministic telemetry `[pipeline_segment_coverage] result=ok|fail covered=0 uncovered=0 mode=stub`
   - degenerate-state guard contract enforcement (`phase=degenerate_state_guards`, runs `node scripts/check-degenerate-state-guards.ts`); triggers when staged paths satisfy `hasDotFiles || hasOpsCommandPaths` and receives staged scope via `--staged-file-list <filelist>` (or `--all-tracked` in full profile); validates declared guard coverage from `scripts/degenerate-state-guard-baseline.json` and emits deterministic telemetry `[degenerate_state_guards] result=ok|fail guarded=<N> unguarded=<N>`
   - benchmark job-id registry enforcement (`phase=benchmark_job_id_registry`, runs `node scripts/check-benchmark-job-id-registry.ts`); triggers when staged paths include `factories/mothership/graphs/**`, `docs/contracts/benchmark-job-id-registry.json`, or `scripts/check-benchmark-job-id-registry.ts`; rejects unregistered `benchmark_job_id` values referenced by mothership graphs and duplicate `job_id` entries in the registry
   - scenario registry budget enforcement (`phase=scenario_registry_budget`, runs `node scripts/check-scenario-registry-budget.ts --all-tracked`); counts all `SCENARIO.md` files under configured roots from `scripts/config/scenario-registry.json` and rejects registry growth above the configured ceiling
   - active-surface manifest enforcement (`phase=active_surface_manifest`, runs `node scripts/check-active-surface-manifest.ts --all-tracked`); rejects missing, ambiguous, or invalid canonical graph/runtime/command classifications
   - active-surface inventory enforcement (`phase=active_surface_inventory`, runs `node scripts/check-active-surface-inventory.ts --all-tracked`); rejects checked-in live active-surface inventory drift and active graph/runtime command-reachability drift
   - Phase 1 gate-readiness enforcement (`phase=phase1_gate_readiness`, runs `node scripts/check-phase1-gate-readiness.ts --all-tracked`); rejects divergence between the canonical active-surface manifest, the three Phase 1 gate scopes (`typed_action_graph_transport`, `runtime_internal_cli_repo_wide`, `command_thinness_active_owner_surface`), hook/CI routing, and the checked-in remaining-violation report
   - Phase 1 ownership mapping enforcement (`phase=phase1_ownership_mapping`, runs `node scripts/check-phase1-ownership-map.ts --all-tracked`); rejects unowned or stale ownership mappings for the remaining active violation set and rejects missing deletion owners for legacy command surfaces still in the current Phase 1 blast radius
   - Phase 1 burndown-finalization enforcement (`phase=phase1_burndown_finalization`, runs `node scripts/check-phase1-burndown-finalization.ts --all-tracked`); rejects missing determinism/boundary classifications for the remaining active violation set, ambiguous wrapper-role graph classifications, and drift between the checked-in final burn-down inventory and the locked scope-finalization contract
   - workflow instrumentation helper enforcement (`phase=workflow_instrumentation_helper_contract`, runs `node scripts/check-workflow-instrumentation-helper-contract.mjs --staged-file-list <filelist>`); rejects direct lifecycle `EventBus.emit(...)` wiring for changed workflow/action instrumentation in `apps/hatch/src/pipeline/**` and rejects direct governed OTel emitter imports outside the helper path
   - canonical event emitter ownership enforcement (`phase=canonical_event_emitter_ownership`, runs `node scripts/check-canonical-event-emitter-ownership.ts --all-tracked`); rejects canonical factory-domain event emitters inside Hatch prompt/manager handler surfaces and other forbidden LLM-owned paths
   - reactor collector enforcement (`phase=reactor_collector_contract`, runs `node scripts/check-reactor-collector-contract.ts --staged-file-list <filelist>` in local hook routing and `--all-tracked` in full proof); rejects newly changed active Hatch control-plane entrypoints that import direct Redis/Langfuse telemetry runtime wiring, rejects missing collector profile/helper routing, and rejects hand-rolled OTLP transport in the shared OTel runtime surface
   - boundary schema registry enforcement (`phase=boundary_schema_contract`, runs `node scripts/check-boundary-schema-contract.ts --all-tracked`); rejects governed boundary outputs that drift from their registered Zod source, rejects missing governed output registrations, rejects newly discovered unregistered boundary authoring modules, and refreshes the canonical registry report when run with `--write`
   - sync OpenAPI registry enforcement (`phase=sync_openapi_contract`, runs `node scripts/check-sync-openapi-contract.ts --all-tracked`); rejects governed synchronous HTTP OpenAPI output drift, rejects newly discovered unregistered sync contract authoring modules, rejects missing registry/report refresh, and rejects runtime sync consumers that stop importing the canonical route contract module
   - asyncapi registry enforcement (`phase=asyncapi_contract`, runs `node scripts/check-asyncapi-contract.ts --all-tracked`); rejects governed AsyncAPI output drift, rejects newly discovered unregistered async contract authoring modules, rejects missing registry/report refresh, and rejects runtime producers or consumers that stop importing the canonical async contract module
   - capability contract registry enforcement (`phase=capability_contract`, runs `node scripts/check-capability-contract.ts --all-tracked`); rejects newly discovered governed capability packages without a checked-in canonical contract source, rejects drifted versioned capability contract outputs, rejects undeclared governed graph or skill entrypoints, rejects package exports that keep pointing at the private `capability.json` dialect, and refreshes the canonical capability contract registry report when run with `--write`
   - capability output registry enforcement (`phase=capability_output_contract`, runs `node scripts/check-capability-output-contract.ts --all-tracked`); rejects governed capability outputs that are missing explicit event/artifact/telemetry declarations, rejects graph capabilities that omit runtime telemetry expectations, rejects output refs that drift away from standard CloudEvents or OCI artifact classes, rejects newly introduced capability output-owner imports or local artifact/telemetry writers that are not registered, and refreshes the canonical capability output registry report when run with `--write`
   - governed capability output helper-path enforcement (`phase=governed_output_path_only`, runs `node scripts/check-governed-output-path-only.ts --all-tracked`); rejects direct governed CloudEvents / OCI / OpenLineage helper imports and direct governed emit API usage in capability source files, and rejects registered producer files that bypass the shared output-owner command path
   - capability output producer discovery fail-closed enforcement (`phase=capability_output_producer_discovery_fail_closed`, runs `node scripts/check-capability-output-producer-discovery-fail-closed.ts --all-tracked`); rejects unclassified capability source files, rejects discovered governed producer files that are not registered, rejects local file writers that are not registered, and rejects producer-path / source-coverage drift
   - capability output runtime parity enforcement (`phase=capability_output_contract_runtime_parity`, runs `node scripts/check-capability-output-contract-runtime-parity.ts --all-tracked`); rejects invalid or unknown governed output refs, rejects undeclared governed event/artifact/telemetry surfaces, and rejects graph-backed capabilities that drift away from the required runtime telemetry surface
   - capability manifest registry enforcement (`phase=capability_manifest_contract`, runs `node scripts/check-capability-manifest-contract.ts --all-tracked`); rejects missing or drifted generated `capability-manifest.v1.json` outputs, rejects governed capability packages that fail to export/publish the standard manifest surface, rejects manifest/package surface drift, rejects missing manifest coverage for contracts/events/artifacts, and rejects legacy handwritten capability manifest paths
   - workflow source registry enforcement (`phase=workflow_source_contract`, runs `node scripts/check-workflow-source-contract.mjs --all-tracked`); rejects migrated runtime graphs that do not declare a schema-validated typed workflow source module, rejects active mothership execution graphs that remain handwritten DOT without canonical typed-source ownership, rejects source-to-runtime ownership drift on graph ids/labels/nodes/edges, rejects undeclared sub-workflow composition refs, and refreshes the typed workflow source schema/registry outputs when run with `--write`
   - governed execution DOT input ban (`phase=governed_execution_dot_input_forbidden`, runs `node scripts/check-governed-execution-dot-input-forbidden.ts --all-tracked`); rejects any governed execution graph under `factories/*/graphs/*.dot` or `packages/*/graphs/*.dot` that is still handwritten instead of generated from canonical typed source, unless the graph is explicitly declared in `docs/contracts/governed-execution-dot-exemptions.json` as an allowed temporary template surface
   - workflow IR parity enforcement (`phase=workflow_ir_parity_contract`, runs `node scripts/check-workflow-ir-parity-contract.mjs --all-tracked`); rejects generated runtime DOT drift for migrated families, rejects missing or drifted checked-in workflow IR documents, rejects source modules that still claim handwritten runtime IR ownership, and refreshes the workflow IR schema/registry outputs when run with `--write`
   - workflow IR claim-truth enforcement (`phase=workflow_ir_claim_truth`, runs `node scripts/check-workflow-ir-claim-truth.mjs --all-tracked`); rejects docs/contracts/code that claim workflow IR is already published when the implementation only proves publication-intent metadata
   - workflow IR publish-or-plan state enforcement (`phase=workflow_ir_publish_or_plan_exclusive`, runs `node scripts/check-workflow-ir-publish-or-plan-exclusive.mjs --all-tracked`); rejects mixed or ambiguous workflow-IR publication states and requires each governed workflow-IR artifact class to be either publication-ready-only or published-and-verified
   - migrated-family handwritten DOT ban (`phase=no_handwritten_dot_for_migrated_families`, runs `node scripts/check-no-handwritten-dot-for-migrated-families.ts --all-tracked`); rejects migrated workflow families that reintroduce handwritten DOT ownership
   - factory composition registry enforcement (`phase=factory_composition_contract`, runs `node scripts/check-factory-composition-contract.ts --all-tracked`); rejects governed factories without generated `factory-composition-manifest.v1.json` outputs, rejects drift between factory config / registry ownership and the generated composition manifests, rejects missing typed policy/bootstrap/artifact-default surfaces, rejects thin-composition factories that retain private execution-graph glue where shared composition should own the runtime path, and refreshes the canonical factory composition registry outputs when run with `--write`
   - factory-local DOT scope enforcement (`phase=factory_local_dot_scope_guard`, runs `node scripts/check-factory-local-dot-scope-guard.ts --all-tracked`); rejects thin-composition factories that compose back into factory-local graph subtrees instead of using the allowed wrapper/composition roles only
   - factory execution-glue ban (`phase=factory_execution_glue_forbidden`, runs `node scripts/check-factory-execution-glue-forbidden.ts --all-tracked`); fails when checked Phase 10 claims still coexist with thin-factory local execution semantics beyond the allowed composition layer
   - factory composition binding truth (`phase=factory_composition_binding_truth`, runs `node scripts/check-factory-composition-binding-truth.ts --all-tracked`); rejects `packages/**` graph bindings that do not resolve to real governed capability surfaces
   - thin-factory end-state guard (`phase=thin_factory_end_state_guard`, runs `node scripts/check-thin-factory-end-state-guard.mjs --all-tracked`); fails when checked Phase 10 claims still coexist with thin-factory execution semantics or stub factories that claim nonexistent bundle surfaces
   - lineage and governance registry enforcement (`phase=lineage_governance_contract`, runs `node scripts/check-lineage-governance-contract.ts --all-tracked`); rejects missing governed OpenLineage registry outputs, rejects missing run/artifact lineage coverage for supported governed classes, rejects duplicate lineage projection helpers outside the shared owner, rejects Marquez/Atlas-style governance dependencies on the hot path, and refreshes the canonical OpenLineage registry outputs when run with `--write`
   - lineage supported-class truth (`phase=lineage_supported_class_truth`, runs `node scripts/check-lineage-supported-class-truth.ts --all-tracked`); rejects run/artifact classes that are still marked supported without real producer/projection ownership
   - lineage projection presence (`phase=lineage_projection_presence`, runs `node scripts/check-lineage-projection-presence.ts --all-tracked`); rejects missing or drifted checked-in OpenLineage-compatible sample projections for supported classes
   - lineage hot-path isolation (`phase=lineage_hot_path_isolation`, runs `node scripts/check-lineage-hot-path-isolation.ts --all-tracked`); rejects governance dependencies or duplicate lineage projection owners outside the shared owner surface
   - governed-surface totality (`phase=governed_surface_totality`, runs `node scripts/check-governed-surface-totality.ts --all-tracked`); rejects reopened-phase domains that still lack a governed owner/gate path
   - claim-to-gate mapping (`phase=claim_to_gate_mapping`, runs `node scripts/check-claim-to-gate-mapping.ts --all-tracked`); rejects checked roadmap claims in the reopened phases that do not reference their governing gate IDs directly
   - CloudEvents registry enforcement (`phase=cloudevents_contract`, runs `node scripts/check-cloudevents-contract.ts --all-tracked`); rejects newly discovered unregistered CloudEvents contract authoring modules, rejects governed runtime producers or consumers that stop importing the canonical CloudEvents contract module, rejects legacy semantic event envelope prefixes on governed event paths, and refreshes the canonical registry report when run with `--write`
   - OCI artifact taxonomy enforcement (`phase=oci_artifact_contract`, runs `node scripts/check-oci-artifact-contract.ts --all-tracked`); rejects governed OCI taxonomy drift, rejects newly discovered unregistered OCI artifact class modules, rejects newly discovered unregistered governed OCI publication callsites, rejects governed publication paths that stop importing the canonical OCI helper surface, rejects governed durable artifact classes that lack canonical lifecycle policy, rejects bespoke lifecycle fields on governed OCI publisher paths unless they are derived from the shared lifecycle helper, rejects direct ORAS usage on governed publication paths, rejects legacy `subjectRef` / `subject_id` attachment models on governed OCI paths, and refreshes the canonical taxonomy report plus metadata schemas when run with `--write`
   - Artifact trust enforcement (`phase=artifact_trust_contract`, runs `node scripts/check-artifact-trust-contract.ts --all-tracked`); rejects required governed artifact classes that lack the canonical trust policy, rejects governed publisher paths that stop importing the shared trust helper or stop exposing trust application on required trust-governed publishes, rejects host-runtime release boundaries that drift away from the canonical trust bundle schema/helper, and refreshes the canonical trust registry report when run with `--write`
   - Dispatch latency SLO enforcement (`phase=dispatch_latency_slo_contract`, runs `node scripts/check-dispatch-latency-slo-contract.ts --all-tracked`); rejects missing or oversized mothership dispatch latency budgets, rejects missing or non-demoted maintenance cadence, rejects daemon runtime drift away from the shared dispatch SLO policy owner, and refreshes the canonical SLO report when run with `--write`
   - Reactor dispatch enforcement (`phase=reactor_dispatch_contract`, runs `node scripts/check-reactor-dispatch-contract.ts --all-tracked`); rejects mothership config drift that collapses dispatch and maintenance back into one graph, rejects missing governed dispatch ownership nodes from the dedicated dispatch reactor, rejects non-hot-path maintenance concerns inside the dispatch reactor, rejects hot-path dispatch logic reappearing in the maintenance supervisor graph, and refreshes the canonical reactor dispatch report when run with `--write`
   - docs policy-scope docs check when triggered (`phase=docs_check`, runs `pnpm docs:check` = policy validation + typed frontmatter/template contract validation + deterministic docs-graph/link-integrity check + state-machine docs check + rationale-doc structure validation + docs hierarchy/index generation check + benchmark query contract validation); trigger set includes policy-scoped docs paths and docs-check implementation dependencies (`docs/docs-policy*.json`, `scripts/docs-policy-check.mjs`, `scripts/lib/docs-policy-validator.ts`, `scripts/docs-check-docs-frontmatter.mjs`, `scripts/lib/docs-frontmatter-validator.mjs`, `scripts/lib/docs-template-framework.ts`, `scripts/docs-check-docs-graph.mjs`, `scripts/lib/docs-graph-checker.mjs`, `scripts/docs-check-state-machines.mjs`, `scripts/docs-check-rationale-docs.mjs`, `scripts/docs-index-generate.mjs`, `scripts/docs-check-benchmark-queries.mjs`, `docs/contracts/langfuse-benchmark-queries.json`, `scripts/lib/live-doc-assets-manifest.ts`)
   - docs freshness review gate (`phase=docs_freshness`, runs `node scripts/docs-check-freshness.mjs`); strict-profile only, all-tracked, and intentionally global instead of path-routed. Governed docs must carry `written`, `reviewed`, `review_policy`, and `status`. Active docs default to `periodic-7`; `generated`, `codebound`, and `historical` docs are exempt from weekly expiry
   - ESLint preflight (`phase=eslint`, runs `node scripts/eslint-gate.mjs`); enforces the shared flat-config boundary/import/custom-rule contract against the staged scope in fast/strict and all tracked files in full
   - repository line-limit enforcement (`phase=line_limit`)
   - factory artifact boundary enforcement (`phase=hatch_artifact_boundary`, runs `node scripts/check-hatch-artifact-boundary.ts --staged-file-list <filelist>`); rejects staged files that look like factory run artifacts leaked to the repo root instead of living under `.hatch/<factory>/` — DOT graph node names materialized as 0-byte files, run state files (`state.json`, `metadata.json`), factory issue specs (`issues/`), and stray checkpoint/trace files
   - module boundary enforcement (`phase=module_boundaries`, runs `node scripts/check-module-boundaries.ts --staged-file-list <filelist>`); rejects cross-package imports that violate monorepo layering: `apps/hatch` must not import from `factory-ops`, `factory-ops` must not import from `apps/hatch` source, `factory-telemetry` must not import from either consumer; contract tests (`*.contract.test.*`) are exempt
   - test topology enforcement (`phase=test_topology`, runs `node scripts/check-test-topology.mjs --staged-file-list <filelist>`); rejects newly staged test files outside the approved checked-in topology roots in `config/testing/topology-enforcement.json`
   - fixture ownership enforcement (`phase=fixture_ownership`, runs `node scripts/check-fixture-ownership.ts --staged-file-list <filelist>`); rejects staged fixture or golden artifacts outside approved owning domains or without deterministic subsystem ownership
   - shared-surface ownership enforcement (`phase=shared_surface_ownership`, runs `node scripts/check-shared-surface-ownership.ts --staged-file-list <filelist>`); rejects new direct implementations of shared operational surfaces outside their owning packages. The first enforced surface is GitHub CLI transport, which must route through `packages/github-adapter`
   - Daily Lens collector ownership enforcement (`phase=daily_lens_collector_ownership`, runs `node scripts/check-daily-lens-collector-ownership.ts --staged-file-list <filelist>`); rejects source-specific GitHub or Langfuse Daily Lens collectors in `factory-ops`, which must compose the implementations from `packages/github-adapter` and `packages/factory-telemetry`
   - behavioral-test boundary enforcement (`phase=test_boundaries`, runs `node scripts/check-test-boundaries.ts --staged-file-list <filelist>`); rejects non-`*.contract.test.*` tests that read production source/graph files directly instead of executing production code
   - test classification enforcement (`phase=test_classification`, runs `node scripts/check-test-classification.ts --staged-file-list <filelist>`); rejects new generic `*.test.*` filenames unless already tracked in the legacy baseline; new tests must declare `.unit`, `.cli`, `.integration`, or `.contract`
   - irreversible-node coverage enforcement (`phase=irreversible_node_coverage`, runs `node scripts/check-irreversible-node-coverage.ts`); core irreversible nodes in `factory_supervisor_tick.dot`, `goal_run.dot`, and `wave_execute.dot` must remain listed in the coverage manifest with both a structural contract test and an executable non-contract test
   - ops export coverage enforcement (`phase=export_coverage`, runs `node scripts/check-export-coverage.ts`); triggers only when `packages/factory-ops/src/commands/**` or `packages/factory-ops/test/**` paths are staged; source-only command edits are checked against staged command exports while still reading the full factory-ops test tree, test-file edits fall back to full factory-ops export coverage, and pre-merge/full remains whole-repo; rejects new uncovered exports, new mutating exports without non-contract behavioral coverage, and new mutating exports whose behavioral tests fail to assert durable side effects (GitHub mutation calls, label/comment state, artifacts, or persisted run state) vs baseline
   - workspace export coverage enforcement (`phase=workspace_export_coverage`, runs `node scripts/check-workspace-export-coverage.mjs`); triggers only when `apps/hatch/src/**` or `packages/factory-telemetry/src/**` paths are staged; source-only edits are checked against the changed source files in the affected workspace, workspace test edits fall back to full affected-workspace coverage, and pre-merge/full remains whole-workspace; rejects new uncovered runtime exports in those workspaces vs the checked-in baseline
   - coverage policy ratchet enforcement (`phase=coverage_policy`, runs `node scripts/check-coverage-policy-ratchet.ts`); triggers only when coverage-policy surfaces change (`apps/hatch/vitest.config.mjs`, `packages/factory-ops/package.json`, `config/testing/package-test-manifests/packages-factory-ops.json`, checker/baseline files); rejects lowered thresholds, removed protected include/src scope, and newly added coverage excludes vs the checked-in baseline
2. **Mandatory non-test quality gates**
   - `gate=platform_invariants` (conditional: runs when staged paths hit shared platform surfaces; emits per-invariant telemetry)
   - `gate=release_quality` (conditional: runs when `hasReleaseQualityTriggerPaths=true`; runs `node scripts/run-platform-invariant-gates.mjs --gate release_quality`; emits per-family `gate_start/gate_pass/gate_failed` telemetry)
   - `gate=lockfile_sync` (runs `node scripts/check-lockfile-sync.ts`; validates workspace names in pnpm-lock.yaml match package.json; catches renames that pass locally but fail `pnpm install --frozen-lockfile` in CI)
   - `gate=build`
   - `gate=runtime_startup_probe` (runs `node scripts/check-runtime-startup-probe.ts` immediately after a successful build; verifies built Hatch entrypoints and the zero-side-effect `hatch-ops` CLI smoke command actually start)
   - `gate=dead_code` (runs `pnpm --silent knip`; currently enforces repo-file reachability through `knip.json` in fast and full profiles)
   - `gate=typecheck`
   - `gate=duplication_scan` (full profile only; runs `pnpm --silent cpd:ci` and fails on duplication threshold breaches)

Preflight gates continue through the remaining preflight set after the first structural failure so one hook run can report all staged structural violations; once any preflight gate fails, non-preflight quality gates and test suites are skipped.
`duplication_scan` is intentionally excluded from the pre-commit strict profile and is enforced in pre-merge through `pnpm --silent qa:pre-merge` (run-gates `--profile full`).
After the full-profile gates and suites pass, pre-merge emits a deterministic whole-repo proof summary from the checked-in package manifests, subsystem ownership map, and spec registry. The summary uses `[whole_repo_quality_proof]` telemetry lines plus a closing `[pre-merge] gate_pass gate=whole_repo_quality_proof ...` record.

### Path-to-suite routing matrix (deterministic)

Docs/dot files are neutral for selective suite routing when mixed with code paths.
Routing buckets apply to non-neutral staged paths only.

| Staged path set | Contract outcome | Deterministic reason/output |
|---|---|---|
| No staged paths | Skip non-test gates and suites | `gates_skipped branch=empty reason=no_staged_paths` and `test_suites_decision action=skip reason=no_staged_paths` |
| Docs-only (`docs/**`, `README.md`, `AGENTS.md`, `CLAUDE.md`, `CODEX.md`) | Run `docs:check`, then `build` + `typecheck`; skip suites | `reason=docs_only` |
| Dot-only (`*.dot` only) | Run DOT validation + DOT lint, then `build` + `typecheck`; skip suites | `reason=dot_only` |
| Docs+dot only (no code paths) | Run relevant preflight checks (`docs:check` + DOT checks as applicable) and mandatory non-test gates; skip suites | `reason=docs_or_dot_only` |
| `apps/hatch/**`, `packages/**`, or `factories/mothership/graphs/**` (without `packages/factory-ops/**`) | Run `test:guard-gates` only | `reason=bucket_guard_only`, `bucket=guard_only`, skip wave suite with `reason=not_selected_by_bucket` |
| Wave-specific factory-ops surfaces only (`packages/factory-ops/src/cli/commands/wave.mjs`, `packages/factory-ops/src/commands/wave-*.mjs`, `packages/factory-ops/src/lib/wave-*.mjs`, `packages/factory-ops/test/wave-*.test.mjs`) without guard bucket paths | Run `test:wave-claim-gates` only | `reason=bucket_wave_claim_only`, `bucket=wave_claim_only`, skip guard suite with `reason=not_selected_by_bucket` |
| Overlap: at least one guard-bucket path + at least one ops path | Run both suites in fixed order: `test:guard-gates` then `test:wave-claim-gates` | `reason=bucket_overlap_guard_wave`, `bucket=all_suites` |

`test:guard-gates` is intentionally narrow: only the guard/engine-critical Hatch tests run there, and its Vitest coverage scope is constrained to the owned guard/runtime source files instead of the whole Hatch app. `test:wave-claim-gates` is also intentionally narrow: only wave-claim / lease-critical factory-ops tests run there, with c8 coverage instrumentation. The broader Hatch and factory-ops suites still run via `pnpm test`, `pnpm test:strict`, and pre-merge.
| Platform-critical shared surfaces only (`apps/hatch/src/factory/**`, `scripts/**`, `.githooks/**`, `factories/_templates/**`, `factories/_shared/**`, `factories/mothership/skills/**`, `packages/factory-telemetry/**`, `examples/external-factories/**`, managed-factory config surfaces such as `factory-registry.json` / `factories/*/kind.json` / `factories/*/factory.config.json`, managed-factory registry consistency surfaces such as `scripts/check-factory-registry-consistency.ts` and `scripts/test/fixtures/managed-factory-registry/**`, plus factory-portability exact paths under `packages/factory-ops/src/{lib,commands,cli/commands}`) | Run `platform_invariants` gate, skip both suites | `reason=platform_invariant_trigger` |
| Other non-neutral paths only | Skip both suites | `reason=bucket_neither_change` |

### Docs-only semantics are strict

`docs_only` is true only when **every** staged path matches the docs policy scope (`docs/docs-policy.json` `docs_policy/v1.in_scope_paths`), currently:
- under `docs/`, or
- one of: `README.md`, `AGENTS.md`, `CLAUDE.md`, `CODEX.md`.

Any staged path outside that set is not `docs_only` (including `.dot`, `scripts/**`, `.githooks/**`, `apps/**`, `packages/**`, `factories/**`).

### Live-doc asset manifest boundary (docs/skills/templates contracts)

Live factory guidance assets are tracked by a deterministic manifest pair:
- code helper: `scripts/lib/live-doc-assets-manifest.ts`
- published contract: `docs/contracts/live-doc-assets.json`

Classifier metadata fields:
- `hasLiveDocAssetPaths`
- `stagedLiveDocAssetCandidates`
- `hasArchivedDocPaths`
- `stagedArchivedDocCandidates`

Boundary rules:
- Live contract-bearing assets include paths such as `docs/skills/**`, `docs/templates/**`, `docs/agent-runbooks/**`, `docs/factory-supervisor-tick.md`, `docs/runbooks/**`, the telemetry query doc (`docs/langfuse-kpis.md`), and `factories/mothership/skills/**`.
- Archived/quarantined docs are explicitly matched (for example `docs/archive/**`, `docs/skills/factory-design-workspace/**`) and excluded from live asset detection even when parent live globs overlap.
- Current routing behavior is unchanged by this metadata: docs-only/dot-only bucket semantics remain deterministic while downstream gates can consume the new live-vs-archived candidates.

| `first_failure phase=quality_gate target=duplication_scan` | Duplication gate failed in pre-merge `full` profile (`pnpm --silent cpd:ci`) because production and/or test duplication exceeded threshold | Run `pnpm --silent cpd:ci` locally to reproduce; isolate with `pnpm --silent cpd` or `pnpm --silent cpd:tests`; remove duplication or adjust scoped code so both scans pass, then rerun |
| `first_failure phase=whole_repo_quality_proof target=whole_repo_quality_proof` | Pre-merge could not map the executed full-profile suites to the checked-in manifests/specs deterministically | Run `node scripts/whole-repo-quality-proof.mjs --telemetry-prefix pre-merge --executed-suite test:guard-gates --executed-suite test:wave-claim-gates --executed-gate build --executed-gate dead_code --executed-gate typecheck --executed-gate duplication_scan`, fix the reported manifest/spec/ownership drift, and rerun `pnpm --silent qa:pre-merge` |
| `first_failure phase=test_suite target=test:guard-gates` | Guard suite failed | Run `pnpm test:guard-gates`, fix failing tests, rerun |
| `first_failure phase=test_suite target=test:wave-claim-gates` | Wave-claim suite failed | Run `pnpm test:wave-claim-gates`, fix failing tests, rerun |

`dot-lint` may also emit non-blocking `severity="warning"` diagnostics (for example `context_flow.undefined_reference` and `context_flow.unused_output_key`) during DOT preflight. These are advisory and do not fail pre-commit by themselves. `scripts/lint-dot.mjs` emits deterministic summary markers (`[lint-dot] result=ok|warning_only|fail ...`) so warning-only runs remain explicitly observable without tripping `first_failure`.

Inline-script debt enforcement is deterministic: new marker debt emits `rule_id="prompt.inline_script_ignore_debt"` plus machine-readable telemetry lines (`inline_script_debt_violation_summary`, `inline_script_debt_added`) and fails `phase=dot_validate` until an explicit reviewed baseline refresh is applied.
